通用标准（适用于所有频道）
1. 图片生成规范 — gen-image skill (maizitech GPT Image 2)，明亮/温馨/写实，无大面积黑色，屏幕浅色主题，1536×1024，压缩至 ≤200KB JPEG (mozjpeg q82)
2. SEO 标准 — canonical URL、OG tags、JSON-LD (Article/Review + FAQPage + BreadcrumbList)、sitemap 更新、IndexNow 自动提报
3. E-E-A-T 标准 — 测试方法论（工具数/天数/评测人数）、联盟披露（页顶）、无供应商关系声明、复测周期（60-90 天）、真实测试数据（Evidence > Adjectives）
4. 写作风格 — Evidence > Adjectives，禁止绝对化营销语（如 "untouchable" "revolutionary"），用测试观察替代主观判断，每段 1-3 句，分节标题给结论
5. 部署流程 — 本地构建 → 用户预览 → 确认 → gen-sitemap.mjs → 单次 wrangler deploy → 单次 git push

5-Dimension Scoring
Quality of Output — 核心功能的实际产出质量（如代码正确性、文本深度、图像质量）。
Ease of Use — 上手难度、UI 清晰度、新用户多久能产出。
Value for Money — 每 1 美元产出的实际价值、免费层慷慨度、成本增长曲线。
Speed & Reliability — 延迟、稳定性和持续使用的一致性。
Support & Docs — 文档深度、社区活跃度、官方支持质量。

总分 = 5 维加权平均，评分必须与测试数据一致。每个维度必须有具体 Notes 说明评分依据。
Writing Style Guidelines
Do: 用测试观察替代营销判断。写具体数字（如 "28% open rate, 6% reply rate"）。同时展示优点和缺点。减少营销语言。
Don't: 绝对化表述（"untouchable" "revolutionary" "the best ever"）。虚构测试数据。只说优点不说缺点。使用未经核实的价格。
Pre-Publish Checklist
  • Score Breakdown dim-table 存在且 5 维都有 Notes
  • FAQ 可见数量 = JSON-LD 数量（5+ 条）
  • 3 组 JSON-LD（Review + FAQPage + Breadcrumb）
  • Disclosure 在页顶
  • 所有价格标注 "as of [month] [year]"
  • 对比表至少 3 个竞品
  • 内链 ≥ 4 个（相关评测/指南/分类）
  • Hero 图片 ≤ 200KB JPEG
  • 字数 ≥ 1,500

Required Sections (v2 In Order)

  • Byline (StackHK News Desk · Updated date)REQUIRED

  • Lead paragraph (1-2 sentences, factual)REQUIRED
  • What's Happening (1-2 short paragraphs)REQUIRED

  • Punch Line (single bold standalone sentence)REQUIRED
  • Media & Industry Reaction (quote cards × 2-3)RECOMMENDED
Writing Style (v2 Editorial)
Deck: 1-2 句钩子，概括文章核心观点。不是描述性摘要，而是有立场的开场白。
Lead: 事实先行（谁/什么/何时/数据）。1-2 句。
段落: 每段 1-3 句。短段落是 v2 的核心风格——避免 3 句以上的连续段落。
Punch Line: 单句独立段落，加粗放大。是整篇文章的"金句"。例: "The people building frontier systems are asking to be slowed down."
媒体评价: 每篇 2-3 条引述卡。来源必须是真实媒体报道（TechCrunch、BBC、Reuters 等）或官方公告（标注 paraphrased）。
Data Pipeline
1. KV 入库: 新闻数据存 KV（site:data → news 数组），含 id/tag/when/title/excerpt/url/image 字段
2. 首页展示: 首页新闻流自动显示最新 5 条
3. 归档页: news.html 按时间倒序显示全部
4. 缩略图: 每篇生成 thumb（480px 宽），tools 页和首页共用
Pre-Publish Checklist
  • Deck 副题存在（news-deck class）
  • 至少 2 条媒体评价引述卡
  • Punch Line 存在（加粗独立段）
  • 配图 hero + thumb 都已上传
  • KV 已入库（news 数组已更新）
  • 所有事实有信源（媒体名或官方链接）
  • 不与已有 30 篇新闻重复

Writing Style (Zapier Benchmark Pattern)
Verdict-as-Headline: 每个比较小节的标题直接给出结论（如 "Semrush wins on breadth: one subscription, five jobs"），读者只看 H2 就能获得全部结论。
Same Prompt Testing: 给两个工具完全相同的任务/Prompt，并排展示结果，用统一标准评分。不分别测试不同的任务。
Evidence > Adjectives: 用具体测试观察替代主观判断。不写 "X is absolutely incredible"，写 "In our test, X produced stronger lighting and material detail."
失败案例: 必须展示两个工具的真实失败案例，比 Pros/Cons 更有说服力。
Pre-Publish Checklist
  • TL;DR box 在页首
  • 14 参数对照表
  • 5 维评分表（含胜方高亮 + Overall）
  • 至少 3 个判词式 H2
  • Choose X/Y/Both 推荐完整
  • Trust footer 含 methodology + tested date
  • Related links 到两篇评测
  • 所有测试数据来自真实测试
  • 价格标注 checked 日期

Universal Standards（全站通用）
Image Generation
Pipeline: gen-image skill (maizitech GPT Image 2) → sharp compression (mozjpeg q82) → site images/
Style: 明亮/温馨/写实，无大面积黑色，电脑屏幕浅色主题
Size: 1536×1024 (3:2) → 压缩 JPEG ≤ 200KB
Usage: Hero 图（每页 1 张），News 额外生成 thumbnail (480px)
场景: 办公室/科技公司/会场/写字楼/商业区/咖啡厅/家庭/休闲旅游等
Prompt 规范: 描述场景 + 光线 + 氛围 + "realistic photography, no dark areas"
SEO Standards
Title: [Topic] (2026): [Descriptor] | StackHK — 核心关键词靠前
Meta: 150-160 字符描述，含核心关键词
Canonical: 每页必须有 canonical URL
OG: og:title + og:description + og:type
JSON-LD: Article 或 Review + FAQPage + BreadcrumbList（三件套）
Sitemap: 每次部署前跑 gen-sitemap.mjs
IndexNow: git push 自动触发
E-E-A-T Standards
Experience: 每篇评测有具体的 Testing Process（不是笼统的 "we tested"），包含测试天数、项目类型、具体任务
Expertise: 展示专业知识（评分有 Notes、对比有数据、分析有深度）
Authoritativeness: 独立立场声明（"never accepts payment for placement"）、无供应商关系披露
Trustworthiness: 联盟披露在页顶、价格标注 checked 日期、失败案例展示、年度复测承诺
Internal Linking
每篇内容至少 4 个站内交叉链接：
